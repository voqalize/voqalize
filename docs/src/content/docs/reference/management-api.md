The HTTP surface behind everything the console and the MCP server do: agents,
sessions, keys and usage. You do not need it to run a call — a brain and a page
are enough — and you will want it the moment you have more than one agent or a
dashboard of your own.

## The outline

- **What the API is for.** Provisioning and reading back. It is not in the call
  path; nothing here runs while a session is up.
- **The resources**: agents (and their `brain_url`), sessions, API keys, usage
  counters, logs.
- **Authentication** — `sk_` on the server, never `pk_`. Cross-links
  [Keys](/build/keys/).
- **The OpenAPI document** is generated by the service itself. This page is
  generated from that document rather than typed, so an endpoint cannot ship
  undocumented and a removed one cannot linger.
- **The three clients** that already speak it: the console, the MCP server, and
  your own code.
