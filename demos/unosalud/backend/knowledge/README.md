# Javier's knowledge of Uno Salud Dental

Three layers, read by `../knowledge.py` at import:

- `L1.md` — always in the prompt: who Uno Salud is, the eleven specialties with their
  published prices, the booking as the visitor lives it, Te llamamos, urgencias, the call
  center, payment, convenios, plans, and what the site does not publish.
- `L2/*.md` — topics for `read_topic`. The specialty and content pages
  (`limpieza.md` … `urgencias.md`), `promociones.md`, `preguntas_frecuentes.md` and
  `mapa_del_sitio.md` are generated by `build.py` from the research; `agendar.md`,
  `planes.md`, `pagos.md`, `convenios.md` and `contacto.md` are written by hand from the
  same research, every fact quoted from the site.
- `L3/*.json` — data, generated by `build.py`: `anchors.json` (the keyed places the
  extension rings; bundled into the extension too), `pages.json`, `clinics.json` (103
  clinics joined to the booking's sucursal ids from `#jsonSucursales`), `faqs.json`,
  `promotions.json`, `motivos.json`.

The site is never fetched. Radware blocks crawlers, and the brain runs where the site is
not served. `build.py` reads the research notes (`content.md`, `cta.md`) and the saved
pages in `demos/unosalud/fixtures/`, and fails if any anchor selector on a saved page does
not match exactly one element (`../dom.py`, a small CSS matcher on the standard library's
HTML parser). Regenerate, from `demos/`:

    uv run python unosalud/backend/knowledge/build.py --research /path/to/research
    uv run python unosalud/backend/knowledge/build.py --check   # anchors only

Known gaps (the crawl was blocked partway): per-clinic hours (only Moneda's), the
`/convenio/<slug>/` detail pages, the campaign terms' bodies, and seven of the nine promo
landings (their offers are read from the card images). Anchors on pages with no saved copy
(ten specialty pages, the convenio categories, PAD/GES/seguro/excedentes) are placed by the
research's block order and carry their heading words as `text`, which the extension falls
back on.
