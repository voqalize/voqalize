# Santander Arena knowledge

What the Santander Arena agent (Javier, a Chrome extension on www.santanderarena.cl) knows, in
three layers. Every fact is the site's own. Nothing is filled in from general knowledge. Where
the site's pages disagree (world ranking 4th vs 5th, 1.5 M vs 1.9 M fans a year), the files
record the disagreement and say which page says what. They do not resolve it.

- **`L1.md`**: always in the prompt, in English, keeping the site's Spanish names. What the
  arena is (formerly Movistar Arena), its claims, getting there and parking, what's on (pointing
  to the event data rather than listing dates), Experiencias Premium, Arena Fans and the
  recognitions, food and drink, tickets (Puntoticket only), the Santander links, the FAQ in brief,
  lost and found, contact, the menu with every path, and the list of L2 topics. About 2.5k tokens.
- **`L2/<topic>.md`**: a topic the agent reads on demand. The file stem is the topic id. Each
  file opens with `# Title`, then a `Sources:` line naming the pages. L2 is hand-written from L3,
  except two files `build.py` generates: `site-map.md` (every page with its exact section
  headings and card titles, plus the menu) and `events-index.md` (every event by date, upcoming
  then past).
- **`L3/`**: generated by `build.py`, the searchable and highlightable raw material.
  - `pages.json`: every page that answered 200 (342 on 2026-10-21: home, 57 pages, 5 listings,
    14 news articles, 265 event pages), one compact record per line. It keeps the keys the
    shared loader reads (`path`, `title`, `description`, `sections: [{heading, text, items}]`,
    `headings`, `faqs: [{q, a}]`, `text`), so `sendpotion/backend/knowledge.py`'s `load()` reads it
    unchanged. It adds `url`, `kind`, `breadcrumbs`, section `level`/`selector`/`pseudo`/
    `dom_text`, FAQ `group`, `cards`, `tickets`, `documents`, `forms` and `iframes`. The
    `build.py` docstring defines each.
  - `events.json`: all 275 events (cartelera plus every event page), sorted by date, with the
    date and time exactly as written, ISO `date`/`time`, `upcoming`, the three Puntoticket links,
    `producer`, the Spanish `description` and an English `summary`.
  - `site.json`: navigation (desktop menu, top bar, mobile menu, footer), contact, social links,
    the footer's legal line, redirects, broken internal links, response headers and outbound
    hosts.
- **`event_notes.json`**: the hand-written English `summary` of every event, keyed by path. It
  sits outside L3 so a re-crawl keeps it. The build lists events without a note.

## Rebuilding

Run from `voqalize/demos`. Playwright is not a demos dependency, so pull it in for the run
(install Chromium once with `playwright install chromium`):

```sh
uv run --no-project --with playwright python santanderarena/backend/knowledge/build.py crawl
uv run --no-project --with playwright python santanderarena/backend/knowledge/build.py crawl --refresh
uv run --no-project python santanderarena/backend/knowledge/build.py crawl --offline
```

`crawl` walks the site breadth first from `/` (about 360 URLs, three minutes) and caches each
page's extraction in `~/.cache/voqalize-santanderarena`. `--refresh` re-renders everything.
`--offline` rebuilds L3 and the two generated L2 files from the cache. `--today YYYY-MM-DD`
sets the day that splits upcoming from past (default: today). After a crawl, write summaries
for new events into `event_notes.json`, re-run `--offline`, and update the hand-written L2
files and L1 if a page changed.

## Things to know about the site

- **Prontus CMS, server-rendered.** Every navigation is a full page load: the extension's
  content script restarts on each page, and there is no client-side routing to hook.
- **Behind Cloudflare.** E-mail addresses are obfuscated (`data-cfemail`) until Cloudflare's
  script runs. The build decodes them itself.
- **Headingless content.** Page titles are `h2.enc-main__title` (rendered in capitals by CSS)
  or, on Experiencias VIP, only a banner image's alt text. Article bodies come from a WYSIWYG
  editor, so many "titles" are not h-tags: `span.titulos` (Terraza Norte / Terraza Escudo), a
  bold-only paragraph (event pages, "POSICIONÁNDOSE EN EL NÚMERO 50."), or `h2.elementor-heading-title`
  (the bars). Several pages have no section headings at all (Santander Suites, Boxes, Food
  trucks, Puntos de venta, Muro, Paseo). `sections` marks the non-h titles `pseudo` and gives a
  `selector` for each.
- **Swiper carousels.** The home "Próximamente" side list, the recognitions row, "Completa tu
  noche" and "Espacios para disfrutar" are Swiper sliders. Their off-screen slides are already
  in the DOM, so `cards` includes them (marked `in_swiper`). To show one, swipe or use its
  pagination dots. Scrolling alone won't bring it into view.
- **The cartelera hides other months.** `/cartelera` ships all 275 event cards in its HTML,
  each with `data-fecha="dd/mm/yyyy"` and `data-tema`, and its month filter detaches the
  cards of other months. The build reads the cards from the server HTML. The year of every
  listed event comes from `data-fecha`. Cards and event pages write the day and month only
  ("5 Noviembre", "5 de Noviembre"). The ten past `/cartelera/conciertos/...` pages that the
  cartelera doesn't list are dated from their Prontus publication date.
- **The FAQ is not an accordion.** `/preguntas-frecuentes` is 18 numbered bold questions
  ("1. ¿Dónde puedo comprar mis entradas?") under five h2 groups, all visible. The only
  accordion on the site is the mobile menu (`.accordionItem`). The build also handles
  `details` and accordion markup, but none is present.
- **Count-up stats.** Numbers on Sobre Nosotros and Sustentabilidad (`.stats__number`)
  animate from 0 when scrolled into view. The build reads their `data-target`.
- **Permissions-Policy blocks the microphone.** Every response carries
  `permissions-policy: geolocation=(), microphone=(), camera=(), …`, so the page itself cannot
  call `getUserMedia`. The extension must capture audio from its own extension page or
  offscreen document, not from the content script's page context. `x-frame-options: SAMEORIGIN`
  stops the site being framed.
- **Tickets are on puntoticket.com.** Every "Comprar tickets", "Comprar estacionamiento",
  "Compra Experiencias VIP", "Ir a reservación" and the VIP banners open puntoticket.com in a new
  tab (`tickets` in pages.json, `*_url` in events.json). Parking and VIP buttons often share
  one Puntoticket product URL. The footer says Puntoticket is the only official channel.
- **Broken links and leftovers from Movistar Arena.** The menu's ¿Cómo llegar? is
  `/como-llegar-a-movistar-arena` (a 301 to `/como-llegar-a-santander-arena`). Links to
  `/santander-arena/...` paths (FAQ → objetos-perdidos and reservas, Bares → bar pages, Food
  trucks → terrazas) are 404s. `site.json` lists every broken link and which page carries it.
- **Puntos de venta** is the Vive Snack food page, not ticket outlets.
