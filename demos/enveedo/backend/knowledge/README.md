# Enveedo knowledge

What the Enveedo guide (Javier, a Chrome extension on enveedo.com) knows, in three layers. Every
fact is the site's own; nothing is filled in from general knowledge. The hand-written layers are in
**English** (the brain answers in English or Spanish from them), keeping the site's product names
(Crown Jewel Analysis, Security Performance OS, CISO Concierge, Enveedopedia, EncyloCISO).

- **`L1.md`**: always in the prompt. Opens with what the site does **not** say (pricing, a trial,
  customer counts, funding, a named award, the 45+ vs 39 frameworks), then who Enveedo is, the
  audiences, the six platform modules, the Security Performance OS pillars, the proof, the frameworks
  in short, partners, cyber insurance, trust, resources, the calls to action and the contacts.
- **`L2/<topic>.md`**: a topic read on demand. The file stem is the topic id; each opens with
  `# Title`, then a `Sources:` line. Hand-written, except `site-map.md`, which `build.py` generates.
  Topics: `platform`, `security-performance-os`, `frameworks`, `partners`, `cyber-insurance`,
  `trust-and-security`, `faq`, `about-and-team`, `resources-and-library`, `integrations`,
  `booking-a-demo`, `site-map`.
- **`L3/`**: generated by `build.py` (crawled 2026-10-28, 1440×900, 35 pages, 516 places: 18 English, 17 Spanish).
  - `anchors.json`: the **catalogue of places**, bundled by the extension and checked by the brain.
  - `pages.json`: one record per page and language (`path, url, lang, twin, kind, title,
    description, headings, sections: [{key, heading, text}], text`); a section's text is what the
    place shows, read after opening it when it is hidden (tab, accordion, toggle).
  - `site.json`: `twins` (English path → Spanish path), `exits` (the scheduler's own page, sign-in,
    blog, Spanish blog, platform PDF), `library` (the gated eBooks and webinars with their titles),
    `contact`.

## `anchors.json`

```jsonc
{
  "_meta": {"site": "https://enveedo.com", "header_px": 66, "scroll_offset_px": 90,
            "viewport": "1440x900", "built": "2026-10-28", "note": "…"},
  "header": [Place, …],   // on every page whose "header" is true: menu, language_switcher
  "footer": [Place, …],   // on every page whose "footer" is true: footer
  "post":   [],           // kept for the colegioeverest adapter's shape; the blog is not catalogued
  "pages": {
    "/":   PageEntry,     // English
    "/es/": PageEntry,    // Spanish twin: SAME keys, selectors looked up per path
    "/frameworks": PageEntry, "/es/frameworks": PageEntry, …
  }
}
```

A **page entry**:

```jsonc
{
  "kind": "home",            // home, platform, enterprise, frameworks, partners, demo, demo_ebook,
                             // contact, about, resources, insurance, faq, trust, library, legal
  "lang": "en",              // "en" | "es"
  "twin": "/es/",            // the other language's path, or null (/webinars-and-ebooks has none)
  "title": "Enveedo | Prove Your Security Program Is Improving",
  "header": true, "footer": true,
  "forms": ["contact"],      // "contact" | "soc2" | "demo" — the form or scheduler the page holds
  "anchors": [Place, …]
}
```

A **place**:

```jsonc
{
  "key": "toggle_with",                     // same on both languages' pages
  "selector": ".cybersecurity-section .cards-container",   // matched exactly one laid-out element
  "label": "The four cards switched to With Enveedo (…)",  // English, for the brain and logs
  "fallback": "#main-content [class*=\"content_bucket-row-3-\"]",  // optional: the section's row
  "reveal": {"click": "#toggle-switch", "open": "#with-label.active"},  // optional
  "hidden": true,                           // optional: the adapter's own (consent box, Submit)
  "optional": true                          // optional: laid out late (the scheduler's frame)
}
```

- **Paths** are lower case, without a trailing slash, except the two homes: `/` and `/es/`. The
  Spanish twin of `/book-a-demo-grl` is `/es/book-a-demo-rsa`; every other twin is `/es` + the path.
- **`selector` first, then `fallback`.** The selector is the HubSpot module wrapper of the
  section's heading (`#hs_cos_wrapper_module_<digits>`), which survives a reorder; `fallback` is the
  section's row (`content_bucket-row-N-`, index-based), worked out on the live page from that module.
  On the Spanish home the rows are shifted by one (an extra hidden row), so the row differs per path;
  the Spanish home's `hero` is the row itself (its module is an empty box).
- **Card grids** have a place per card, besides the section's own: the platform's six module
  cards (`mod_*`), integration capabilities (`int_*`), automation features (`auto_*`) and
  dashboards (`dash_*`); the home page's impact numbers (`impact_*`) and testimonials
  (`testimonial_*`); the Security Performance OS stall cards (`stall_*`) and results
  (`result_*`); the partner cards (`partner_*`) and benefits (`benefit_*`); the /book-a-demo
  cards (`start_*`); the about page's principles (`principle_*`); the cyber insurance benefit
  and feature cards; the trust center's control cards (`ctrl_*`). A card is its grid's n-th item
  under the module (`… .cyber-card:nth-child(n)`), with a class-only candidate after it. None
  hides its text: no reveal.
- **A section with its cards** (`modules`, `integration_capabilities`, `automation`,
  `dashboards`, `impact_stats`, `why_stall`, `strategic_advantage`, `why_partner`,
  `start_with`, `principles`) is the whole top-level section that holds the heading's module,
  `#main-content .dnd-section:has(#hs_cos_wrapper_…)`, not the heading alone; the adapter rings
  it whole even when it is taller than the screen (`benefits` on /partners is its column).
- The about page's Spanish principles sit in shifted module ids (the first English id holds
  another principle there), so a place can list Spanish-only candidates (`Place.es`).
- **Scroll** with a 90 px offset (`scroll_offset_px`): the sticky header is 66 px once scrolled.
- **`reveal`**: the place is hidden until its own control is pressed. To show it: if `open`
  matches nothing, click `click` (`element.click()` is enough, verified), wait for it to open, then
  scroll to and ring `selector`. Revealed places: the home page's four "How Enveedo Works" tabs
  (`how_business_first`, `how_integration`, `how_automation`, `how_reporting`), the Without/With
  toggle (`toggle_without`, `toggle_with`: one switch `#toggle-switch`, "open" is the active label),
  the 15 FAQ accordions (`faq_*`), and the about page's Mission/Vision/Philosophy tabs
  (`tab_mission`, `tab_vision`, `tab_philosophy`). The 39 framework cards (`fw_*`) are laid out
  and need no reveal.
- `hidden` places are never offered to the model: `contact_consent`, `contact_submit` (on /contact
  and /frameworks), `soc2_consent`, `soc2_submit` (/trust-center), `become_partner` (/partners), for
  the adapter to ring them for the visitor. Nothing ever presses them.

Every selector was checked on the live page in both languages: it matched exactly one laid-out
element (a reveal: after its control opened it), or it was dropped and printed. The two Spanish
pages whose module ids differ (`/es/` hero, integrations and testimonials; `/es/enveedo_platform`
hero; four `/es/security-performance-os` rows; seven `/es/frameworks` cards) list the Spanish id
as a second candidate in `build.py`.

## Rebuilding

Run from `voqalize/demos`. Playwright is not a demos dependency, so pull it in for the run
(Chromium once with `playwright install chromium`). The browser is always headless.

```sh
uv run --no-project --with playwright python enveedo/backend/knowledge/build.py crawl
uv run --no-project --with playwright python enveedo/backend/knowledge/build.py crawl --refresh
uv run --no-project python enveedo/backend/knowledge/build.py crawl --offline
```

`crawl` renders each page of the catalogue in both languages, 4 seconds apart (a real company's
site), caching each in `~/.cache/voqalize-enveedo` (`$XDG_CACHE_HOME`). A cached page is not
rendered again unless `--refresh`; `--offline` rebuilds from the cache only. No form is filled or
submitted and the cookie banner is never pressed; the only presses are the site's own tabs,
accordions and toggle, to check `reveal`. After a crawl, check the printed `dropped` lines (a
module id changes when Enveedo's marketers recreate a module), then update L1 and the L2 topics if
a page changed.

## Things to know about the site

- **HubSpot CMS**, full page load on every navigation. Header sticky (66 px), cookie banner
  `#hs-eu-cookie-confirmation` (never pressed by us), HubSpot chat launcher bottom right.
- **Site bugs, not repeated**: the English header's "Platform" and "Security Performance OS" link to
  the Spanish pages, and Spanish CTAs ("Agenda una Demo") link to English pages; the /book-a-demo
  hero has typos; several `<title>`s are wrong (/partners is "Enveedo Platform", /webinars-and-ebooks
  is "FAQ"); the FAQ points to a "Book Risk Assessment" button on the home page that is only on
  /cyber-insurance; the about page's "Book a Demo" goes to an eBook request page.
- Forms are HubSpot "formsnext", inline (not iframes), with English labels on Spanish pages; the
  contact form has invisible reCAPTCHA. The demo scheduler is a cross-origin HubSpot Meetings frame
  that loads 5–9 s after the page.
