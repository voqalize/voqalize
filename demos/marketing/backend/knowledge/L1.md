## IDENTITY

Voqalize — **in-app voice agents**. Voice mode for a web or mobile app that
already exists. Page tagline: *"You keep the agent, the models, the prompts, the
tools and the data; we run the voice."*
Not telephony. The screen is there, so the agent points at it rather than reading
it out.

The one sentence everything hangs off: **the customer writes the *brain* — a
WebSocket service in their own backend; Voqalize runs everything below the text
boundary.** Text and typed events cross. Customer code never touches audio.

Free plan: **350 minutes at signup, no credit card**; paid plans on the pricing
page. Processed and stored in India; a US region is planned, not
selectable.

## FACTS

### Integration

- Touch points. Browser: one `POST /api/v1/sessions.connect`, then stock **pipecat** — no library of ours in the page. Server: **one WebSocket route**.
- Voqalize dials `{brain_url}?session_id={session_id}`, the customer's path verbatim. **One connection per session**, opened just-in-time, closed at end of call.
- Connect body: `agent_id` (required), `init` (opaque → `session.init`, stored; send identifiers, not PII), `config` (`tts`/`stt`/`idle`/`record`), `display_name`, `metadata` (≤10 keys, ≤256 chars). Strict — an undeclared key is `422`.
- Response: `webrtc_request_params` + `session_id`, forwarded verbatim to pipecat's transport. **A machine, not a load balancer** — the node is chosen at mint time, so it can't be a constant in the page. Media is direct UDP to it; nothing of ours relays it.
- `Brain` is a Python class of callbacks: `greet`, `on_user_message`, `on_user_idle`, `on_rtvi`, `on_finalize`, `on_session_start/end`, `on_error`. Speaking callbacks are async generators yielding `SpeechStart`/`SpeechChunk`/`SpeechEnd`. `greet` is a **static string**, never a model call.
- **Behind the URL, anything** — one agent, many agents, routing, hand-off. Voqalize does not inspect it; there is no notion of "agent" on the wire past the `agent_id` that chose the URL.
- **State is the brain's**, entirely. No reconnection, so nothing to rehydrate; what must survive goes to the customer's own store.
- Other languages: implement the published wire; the SDK's conformance harness is the compatibility path. → `l2/wire-and-brain.md`

### The wire

- **Protobuf**, versioned, published as `proto/` in the public repo. Planes on one socket: speech/turns, and RTVI carried verbatim.
- Nothing on the wire declares a tool, carries a schema or names a model. The boundary is **text**. Hence no LangChain/ADK/OpenAI-Agents adapter, and none coming — the framework lives inside `on_user_message`.
- Actions are the brain's second output: a typed pydantic model, dispatched as RTVI `ui-command`, read by stock pipecat's `useUICommandHandler`. App→brain is `ui-event`, parsed by `AppEvents.parse` — so a user editing the document by hand is an event the developer models. `voqalize types` generates the TypeScript unions from both, so adding one is a **compile error until handled**.
- `bot-*`/`llm-*` never cross to the brain — they are the voice tier's own assertions about the media, and a brain must not forge them. The whitelist *is* the security property.
- A typed sentence (`client.sendText`) is committed as a **user turn**, not a message, and is always answered aloud.

### Keys and auth

- Every credential names **one agent**. No tenant-wide key — there was one (`ak_`), removed 2026-08-12.
- `sk_` secret: backend holds it, mints sessions, also the Cortex credential. `pk_` publishable: ships in page source, carries a **non-empty origin allowlist** the API enforces; empty denies. A `pk_` may turn recording *off*, never *on*.
- Voqalize authenticates to the brain with the **brain-connection token**: short-lived RS256 JWT, `iss=pygato`, `aud=brain`, `sub == session_id`. SDK verifies against embedded public keys.
- Management (agents, keys, call history) is **MCP over OAuth**, not a bearer REST API — deliberate. One HTTP route takes a key, and it starts a call.

### Runtime, failure, limits

- **The socket is the session and is not reconnected.** First connect retries from 100 ms, gives up at **10 s**; close code 4000 stops retries. After the brain answers, any close ends the call.
- The only sentences Voqalize ever puts in the agent's mouth are fixed. Unreachable brain → *"Sorry — I can't reach the assistant right now. Please try again shortly."*, call ends 6 s later. Turn with no text within **10 s** → *"Sorry — that's taking longer than I expected."* and **the session stays up**; only that turn's answer is lost.
- Interruption: stops mid-word, reports the **heard prefix** per speech unit on `Finalize`. History holds what the user heard, not what the brain intended. Watermark is one-way.
- **Never block a turn.** Work that outlives its turn is normal — announce, return, open a new speech unit when the result lands. Dependencies are unfabricable parameters on the next call, not waits.
- Session cap **one hour** (`end_reason: max_duration`). `idle.timeout_ms` defaults **0 = off**, ceiling 300000; `on_user_idle` never fires until set.
- Concurrent sessions are **set by the plan** (Free 2, Starter 5, Growth 25, Enterprise sized) — a peak above a plan is a conversation first. Management API rate limited per tenant (`429` + `Retry-After`); MCP 120 tool calls/min/tenant.
- No latency figure is published at any layer — the instrument ships, the claim does not. → `l2/latency-and-failure.md`

### Speech

- One recognizer, no model field: English, Spanish, French, Italian, Japanese and **22 Indic languages**, for recognition and synthesis alike. This page's own call switches only among English and the Indic languages — offer those, not the others. No published per-language accuracy — don't claim parity; offer the Hindi `orderdesk` demo or a scoped evaluation.
- A voice id carries its own engine in its prefix; there is no separate model field. `omnivoice/*` is the voice-cloning engine that speaks Indian English and the Indic languages — `gauri` female, `gaurav` male. `kokoro/*` are American and British English checkpoints of each gender; kokoro and omnivoice also speak Spanish, French, Italian and Japanese. Recognizer and synthesizer alike are **ours, tuned and served on our own GPUs** — not a marked-up passthrough. Which languages a voice speaks is a fact about the speech tier, not the wire: the roster is at `/reference/catalog`.
- `stt.language` picks the recognizer; `tts.language` picks **which recorded reference clip the voice is cloned from**, not a text tag. Half-stated language → `ConfigError`. A speaking language with no clip is **rejected**, never silently substituted.
- Set at connect (`config`) or mid-call by the brain (`session.configure`). **Later wins; the brain has the last word.** STT at the next turn boundary, TTS at the next speech unit, never mid-utterance.
- No engine knob, no VAD/end-of-turn knobs, no BYO speech vendor on the self-serve path. BYO TTS and a custom brand voice are **enterprise**. → `l2/speech-and-languages.md`

### Avatar

- Rendered **on the device** from audio plus a thin cue stream on the data channel — no video track, no GPU, no per-minute avatar meter. Photograph on shallow geometry; eyes, teeth, lip line are geometry rather than paint.
- **MIT**, works with any pipecat agent: `@voqalize/avatar` (npm), `voqalize-avatar` (PyPI), `github.com/voqalize/avatar`. Line-art and painted faces MIT, no attribution; the 2.5-D characters' binaries CC-BY 4.0. Standalone use is the design, not a loophole.
- On page: tanya (in the recording), tushar, tess, tara. Custom avatars are enterprise.

### Observability

- Per turn: user stopped speaking → words recognized → brain dialled → brain's first byte → first audible sample. The brain's span is by far the widest; the page draws it to scale.
- Stored: session record and `init`, lifecycle and wire events, transcripts, Voqalize logs; audio only when recording was on. **Not** stored: brain model history and brain logs — they stay in the customer's environment.
- Reads: console and MCP (`list_sessions`, `get_call_record`, `get_session_logs`, `get_session_events`, `get_recordings`, `get_usage`) — so timings export, nothing is console-only. Record first (contract), logs second (evidence); events are the only read available *while* the call runs. **No webhook, no streaming events API.**
- Recording **off by default**, per call, one WebM track per role (`user`, `agent`), sample-aligned and equal-length. Download URLs are short-lived signed credentials. **Retention is 30 days**, recordings included — keep your own copy of anything needed longer.
- Testing: `voqalize.conformance` is a fake Voqalize on a real socket, driven in **text mode** — `user_says("…")` in, a `Turn` with `.text` out, plus `barge_in`, `user_idle`, `collect_ui_commands`. Real token verification, deterministic barge-in timing, no browser or model. Runs in CI. → `l2/observability-and-testing.md`

### Deployment

- **Inbound** (default): customer exposes one authenticated `wss://` route; Voqalize dials in; no relay. **Cortex** (fallback, and the **local-dev default**): the brain dials *out* to a stateless relay, legs matched on a rendezvous scope derived from credentials, never from the URL. **Same brain code either way** — a laptop behind NAT needs no tunnel.
- An agent with no brain cannot take a call — `409 agent_not_configured`. No hosted fallback brain any more, deliberately.
- Cloud hosted on subscription; for enterprises, deployable into the customer's **cloud VPC with no external dependency** — speech models included, on their GPUs, nothing phoning home.
- Page states ISO 27001, SOC 2, GDPR compliant, DPDP compliant, plus role-based access, audit trail, residency controls. **The SOC 2 type is not stated publicly — never assert one.**
- Forward-deployed engineering: **our engineers work alongside the customer's**, as part of an enterprise engagement. No delivery partner is named publicly — never name one. → `l2/deployment-and-vpc.md`

## THE OBJECTIONS THAT ACTUALLY COME UP

Short answers; the L2 file carries the argument.

- **Why not OpenAI/Gemini realtime voice directly?** Different trade, not a worse one. There the agent moves into the vendor: their model, prompts and tools shipped over, no VPC, no screen control. Here one WebSocket route and the agent stays put. Greenfield voice-only with no existing agent — a realtime API is fine, say so. → `company-and-comparison.md`
- **Why not assemble pipecat + WebRTC + a speech vendor myself?** Entirely possible; some teams should. What it costs: WebRTC at concurrency, endpointing and barge-in tuned until interruption feels right, heard-prefix bookkeeping, speech vendors' latency and language coverage, avatar, aligned recording, per-turn measurement, a CI harness that drives voice without a microphone. Months, none of it the product being shipped. → `company-and-comparison.md`
- **What's the moat if the avatar is MIT and the client is pipecat?** The giveaways are deliberate — neither is the hard part. Ours: two speech models on our own GPUs, turn-taking that survives barge-in, WebRTC operated at real concurrency, the whole tier deployable inside someone else's VPC. Two years of production is the part that can't be cloned in a quarter.
- **What am I paying for besides transport?** Transport is the cheapest thing on that list. → `pricing-and-plans.md`
- **Is it safe in front of real customers?** The runtime has been in production two years. Growth carries a 99.5% uptime SLA, Enterprise 99.9%; retention is 30 days. A launch above a plan's concurrency is a conversation at `support@voqalize.com`. → `pricing-and-plans.md`
- **What does it do that a chatbot doesn't?** It talks while the app keeps working — sees the screen, moves the user, fills things in, hands control back.
- **Do I need engineers?** Yes. Someone writes the brain. There is no no-code path, and the fast path for an engineer is a coding agent pointed at the MCP server.
