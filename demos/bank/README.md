# Anvaya Bank

A fictional Indian retail bank: a public website and a complete signed-in banking app, with one
voice assistant who drives the screen while he talks. Anvaya Bank, its products, rates, fees and its
customer (Aditi Sharma) are all sample data; nothing here is a real bank, product or person.

It replaces three older demos (aura, kiosk, lead_qual) with one suite.

## Landing pages and what the assistant does there

| landing | job |
|---|---|
| `/demos/bank/app` | **Banking assistant.** Answers from the customer's own accounts, cards and transactions and opens the screen the answer lives on: "what was this ₹4,999 charge?" opens that transaction; "how much did I spend on food last month?" opens Insights on that category; "block my debit card" puts a confirmation sheet on screen and acts only after a yes (spoken or tapped). Bills, transfers, FDs, card limits and controls, EMI conversion and the pre-approved loan go through the same sheet. Cross-sell offers (a pre-approved personal loan, a card upgrade) sit in the app, and the assistant switches into card or loan mode when the customer goes there. |
| `/demos/bank/open-account` | **Account opening guide.** A six-step savings application (personal details, address, KYC with masked sample PAN and Aadhaar, nominee, account variant, review) that fills in as the customer talks, with a one-line reason for each step. |
| `/demos/bank/cards` | **Credit card advisor.** Five authored cards; ranks them by yearly value from how the customer spends (or, signed in, from her real last-three-months spend), compares side by side, takes an application, and converts a card spend to EMI with every tenure's EMI on screen. |
| `/demos/bank/loans` | **Loan advisor.** Home, personal, gold and car loans: eligibility from income and existing EMIs, an EMI calculator that shows its working, the documents list, and an application that ends in a qualified lead card for the bank's team. |
| `/demos/bank/` | The front desk: finds out what the visitor wants and takes them there. |

Sign-in is a mock: one tap, no real authentication.

## How it is built

- `CONTRACT.md` — the agreement between the page and the brain: routes, the Stage moves, the forms'
  field names, the page's events, and the maths both sides share.
- `persona.json` — the character (avatar id, display name, voice per language, languages, default).
- `data/products.json` (authored catalogue) and `data/customer.json` (generated by
  `data/build_customer.py` with a fixed seed). Both sides read the same files. Dates are kept as
  "days ago", so the data is always current.
- `backend/` — `BankBrain`, an `OpenAIBrain` at `reasoning="medium"`. Every on-screen act is a Stage
  move declared in `frontend/src/stage/scene.json` and generated into `backend/stage_gen.py` and
  `frontend/src/stage/scene.gen.ts`. Tools compute from the data, send moves and return at once;
  reads the model must speak from are `@needs_result_now`.
- `frontend/` — a Vite + React app. Every move also works by click alone; the voice layer is Stage's
  performers over the same stores the buttons use. `?debug=1` adds a console that fires any move by
  hand (`window.__bankMove(id, args)`).

## Redial

A call survives the brain's socket dropping (SDK 0.15.0 `Config.redial`, on wherever Voqalize offers
it). The live brain is held by session id in `backend/rejoin.py` for two minutes after a drop; the
brain Voqalize's redial starts adopts the whole call (screen, language, history, a sheet awaiting a
yes, her cards and balances) and does not greet again. Details in `CONTRACT.md`, Redial.

## Run it

```sh
# brain tests (no network, no key)
cd demos && uv run pytest tests/test_bank_e2e.py tests/test_demo_voice_contract.py -q

# the page
cd demos/bank/frontend && pnpm install --ignore-workspace && pnpm dev --port 5404
# open http://localhost:5404/demos/bank/  (add ?debug=1 for the move console)
```

For a live call, set `VITE_AGENT_ID` and `VITE_PUBLISHABLE_KEY` (see `frontend/.env.example`) for an
agent whose brain URL points at `wss://<brain host>/bank`. Without them the site works fully by click,
and the dock says voice is not configured in this build.

## Change the character or add a language

Edit **`persona.json`** only:

- `character` — the avatar character id; `name` — the display name the page shows ("Talk to Arjun");
  `spoken_names` — the name as the voice says it in each language.
- `voices` — the voice id per language; `languages` — the languages the toggle offers;
  `default_language`; `language_labels` (the toggle's labels) and `language_names`.

The page reads it for the dock, the toggle and alt text; the brain reads it for the greeting, the
voice and both speech legs, which it sets together in `on_session_start` and again on a switch.
Adding a language also needs its written lines in `backend/prompt.py` (`LINES`, `TIMES` and the
greetings), and a voice that speaks it: check the voice roster (`/api/v1/catalog.get`) first.
