# Anvaya Bank — UI ↔ brain contract

Anvaya Bank is a **fictional** Indian retail bank and a Voqalize voice demo: a public website and a
complete signed-in banking app. One brain (`backend/brain.py`, `OpenAIBrain`) plays the bank's
assistant, whose character, voice and languages live in **`persona.json`** only (today: Arjun,
voice `omnivoice/arjun`, English and Hindi). It has four jobs, one per landing page:

| landing | mode | job |
|---|---|---|
| `/app` (and `/app/*`) | `banking` | answers from the customer's own data and opens the screen the answer lives on; anything that changes state goes through a confirmation sheet |
| `/open-account` | `account` | fills the six-step savings account application as the customer talks, explaining each step |
| `/cards` (and `/cards/*`) | `cards` | card advisor: compare ranked from spend, apply, EMI conversion |
| `/loans` (and `/loans/*`) | `loans` | loan advisor: eligibility, EMI calculator with the maths, documents, application ending in a qualified lead card |
| `/`, `/login` | `home` | the bank's front desk: routes the visitor to one of the four |

The call starts with `init = {landing, path, lang, signed_in}` (`landing` is the mode above, `lang` is
`en`/`hi` from the toggle). The brain follows the visitor: every `page_viewed` sets the mode from the
path, so a banking call that opens `/cards` is a card advisor from that turn.

This file is the agreement between `frontend/` and `backend/`. Change it only in the same PR as the code.

## Data (both sides read the same files)

- `data/products.json` — authored, fictional: brand, savings variants, account-opening steps and
  choices, 5 credit cards, the card value model, EMI tenures and rates, 4 loans (home, personal, gold,
  car), FD rates, billers, spend categories.
- `data/customer.json` — generated by `data/build_customer.py` (fixed seed; never edit by hand): the
  one signed-in customer, Aditi Sharma: savings `sb` and current `ca` accounts, debit and credit cards,
  statements, beneficiaries, registered billers, FDs, a car loan, two offers (a pre-approved personal
  loan and a card upgrade) and ~200 transactions (`sb`, `ca`, `cc`).
- Dates are `days_ago` / `days_from_now`; each side turns them into dates against **today**, so the data
  is always fresh. A month is a calendar month (`YYYY-MM`).
- **No invented facts.** The agent states only numbers from these files or computed by the maths
  below. UI copy is Indian English: ₹ with Indian grouping (₹1,25,000), dates `07 Nov 2026`.
- PAN and Aadhaar are sample values and are always **displayed masked** (`ABCXX1234F` → `ABC•••••4F`,
  Aadhaar → `XXXX XXXX 1234`).

## Maths (identical on both sides: `frontend/src/lib/bankmath.ts`, `backend/bankmath.py`)

- **EMI**: `P·r·(1+r)^n / ((1+r)^n − 1)`, `r = rate/12/100`, rounded to the rupee.
- **Card EMI** (`products.emi`): EMI at the tenure's rate; interest = EMI·n − P; processing fee =
  max(₹199, 1% of P); GST 18% on the fee.
- **Card value** (`products.card_value_model`): for each category, rate = the card's rate for it (or
  its `base`); points: spend·rate/`earn_per`(100)·`point_value`; cashback: spend·rate/100. Accelerated
  categories (dining, online, groceries, travel) earn at min(rate, base) plus an *extra* above base,
  and the extra is capped monthly (`accelerated_points_monthly`·`point_value`, or
  `accelerated_cashback_monthly`); fuel is capped by `fuel_cashback_monthly` when set. Plus the fuel
  surcharge saving min(1% of fuel, cap)·12, plus lounge value when travel ≥ ₹5,000 a month
  (min(domestic, 8)·₹1,000 + min(international, 2)·₹2,500; unlimited counts 8), minus the annual fee
  unless 12 × monthly spend ≥ `fee_waiver_spend`. Ranked by this yearly net value.
- **Customer's spend profile**: debits of the last 90 days from `sb` and `cc`, by the category's
  `card_category`, ÷ 3, rounded to ₹100.
- **Loan eligibility**: max EMI = income·FOIR − existing EMIs; max loan = max EMI·((1+r)^n − 1)/(r(1+r)^n)
  at the typical rate, floored to ₹10,000, capped at `amount_max`. Gold: grams·₹7,200·75%, floored to ₹1,000.
- **FD**: cumulative = P·(1 + rate/400)^(4·months/12); monthly / quarterly payout = P·rate/100/12 (or /4).

single tap (and `nav.open` to an app screen signs in on the way, as a demo convenience, saying so).

## Brain → page: Stage moves (`frontend/src/stage/scene.json`, generated into `backend/stage_gen.py` and `frontend/src/stage/scene.gen.ts`)

Regenerate after editing `scene.json`:
`cd demos && uv run voqalize stage gen bank/frontend/src/stage/scene.json --py bank/backend/stage_gen.py --ts bank/frontend/src/stage/scene.gen.ts`

Every move rings its target before it changes anything, refuses with the options the page offers
instead of guessing, and returns one short line. Every move also works by click alone (the page is a
complete bank without voice). `?debug=1` adds a console that fires any move by hand.

- `ui.show {thing}` — the one cue (`{show: Reward points}`): ring a `data-stage-thing` on screen.
- `nav.open {screen, id?}` — open a screen.
- `txn.find {account?, category?, query?, from_days_ago?, to_days_ago?, min_amount?, max_amount?, direction?, label?}`
  — the transactions screen with those filters set (the page applies `filterTxns`, the same filter as
  `bank.filter_txns`); returns "N transactions, total ₹X".
- `txn.open {txn_id}` — the transaction's detail panel.
- `insights.show {month, category?}` — insights for the month, the category's row ringed.
- `confirm.ask {action_id, kind, card?, control?, value?, amount?, target?, from_account?, tenure_months?, payout?}`
  — the confirmation sheet. Kinds: `card_block`, `card_unblock` (card), `card_control` (card, control ∈
  international|online|contactless|atm, value on|off), `card_limit` (card, control ∈
  atm_daily|pos_daily|online_daily, value = rupees, ≤ limits_max), `bill_pay` (target biller id,
  amount, from_account), `transfer` (target beneficiary id, amount, from_account), `fd_book` (amount,
  tenure_months, payout, from_account), `emi_convert` (target txn id, tenure_months), `offer_accept`
  (target offer id, amount?, tenure_months?). The page builds the summary itself from its data and
  refuses what it cannot do (limit above max, amount above balance, txn not EMI-eligible).
- `confirm.answer {action_id, yes}` — presses Confirm / Cancel; the result detail carries the reference.
- `form.fill {form, field, value}` / `form.step {form, step}` / `form.submit {form}`.
- `cards.compare {card_ids[], dining?, online?, groceries?, travel?, fuel?, utilities?, other?}`.
- `emi.plan {txn_id? | amount?, tenure_months}`.
- `loan.calc {loan_type, amount, tenure_months, rate?}`.
- `loan.eligibility {loan_type, monthly_income?, existing_emis?, tenure_months?, gold_grams?}`.

Plain action (not a Stage move): `language_changed {language}` — the dock's toggle follows the call.

### Forms (field names are the contract)

- `open_account`: step 1 `full_name, date_of_birth (YYYY-MM-DD), gender, mobile (10 digits), email`;
  step 2 `address_line, city, state, pincode (6 digits), residence_type`; step 3 `pan (AAAAA9999A),
  aadhaar (12 digits), occupation, annual_income`; step 4 `nominee_name, nominee_relation, nominee_dob`;
  step 5 `variant, debit_card, cheque_book`; step 6 review. Choices: `products.account_opening.choices`.
  Submit → reference `ANV-SB-<6 digits>`, "video KYC link sent" confirmation.
- `card_apply`: `card_id, full_name, mobile, pan, employment, monthly_income, city`. Submit → `ANV-CC-<6 digits>`.
- `loan_apply`: `loan_type, full_name, mobile, city, employment, employer, monthly_income, existing_emis,
  amount, tenure_months, property_value (home), gold_grams (gold), car_price (car), preferred_time`.
  Submit → a **qualified lead card**: lead id `ANV-LD-<6 digits>`, product, amount, tenure, EMI,
  eligibility verdict (amount within the eligible maximum or not), documents to keep ready, callback
  slot, "assigned to the <product> team, <city>".

## Page → brain events (`client.sendUIEvent`, each with `by: "visitor" | "agent"`)

`page_viewed {path, screen, signed_in}`, `signed_in {customer_id}`, `signed_out {}`,
`txn_opened {txn_id}`, `card_control_changed {card, control, value}`,
`action_done {action_id, kind, outcome: done|cancelled, reference?, summary}` (a confirmation sheet was
answered, by tap or by `confirm.answer`; a sheet the visitor opened by hand gets an `action_id` starting
`V`), `form_changed {form, step, filled[], missing[]}` (field names only),
`form_submitted {form, reference, summary}`, `cards_profile_changed {dining… other, top[]}`,
`loan_calc_changed {loan_type, amount, tenure_months, rate, emi}`, `language_requested {language}`.
Stage's own `stage_result` / `stage_hello` / `stage_progress` ride beside them.
