# Agroplanet knowledge

What the Agroplanet agent (Javier, in a Chrome extension on www.agroplanet.cl) knows, in
three layers. Every fact is the site's own, read on 2026-10-29 from www.agroplanet.cl and
api.agroplanet.cl, plus 2023 Wayback copies of ayuda.agroplanet.cl (the live help site did
not answer from India) where a topic says so; nothing is filled in from general knowledge.
Where the site disagrees with itself the disagreement is written down, not resolved. **No
file holds a product price or a stock level**: prices, "Confirmar precio en tienda" and
totals are read live in the visitor's browser and reach the brain as app and stage events.

Much of the site's policy text is shared with the sister site Autoplanet and names
Autoplanet / autoplanet.cl. The hand-written topics keep the substance, say "Agroplanet"
only where the page itself does, open with a one-line note for the brain author, and drop
stale campaign dates (CyberMonday 2023). `pages.json` keeps the pages' own words and marks
those pages `autoplanet_text: true`.

- **`L1.md`**: always in the prompt, ~2k tokens, hand-written and dated: who Agroplanet is
  (since 1956, 22 stores, 10.000+ products, same company as Autoplanet), the 10 top
  categories with their paths, how buying works (cart → Cotizar → Formulario de cotización
  → Agroplanet confirms by email; no online payment; the RUT and "Crear cotización" are the
  visitor's), prices ("Confirmar precio en tienda", the PDP notice), hours, WhatsApp, and
  one line per policy with its topic id.
- **`L2/<topic>.md`**: read on demand; the file stem is the topic id; each opens with
  `# Title` and a `Sources:` line. Hand-written: `despacho`, `cambios-y-devoluciones`,
  `garantia-baterias`, `como-cotizar`, `ofertas` (the month's home banners by category and
  the campaign switch; volatile, re-read every month), `contacto`, `sobre-agroplanet`,
  `terminos` (archived 2023), `privacidad`, `bases-legales`. Generated by `build.py maps`: `site-map` (pages,
  headings, accordion panel titles), `categorias` (the tree with codes, paths and filters)
  and `tiendas` (from `stores.json`; pcfactory's is hand-written).
- **`L3/`**, built by `build.py` and committed, one object a line inside `[ ]`:
  - `categories.json` — the 290 visible nodes of the "Todas las categorías" menu
    (`menu/getFullHierachyByID`; `visible:false` nodes and their children left out, "Ver
    todo" entries folded into their column as an alias): `code, path, name, parent,
    parent_code, level, aliases, page_name, products, facets`. `facets` (levels 1 and 2
    only) is `[{name, param, options, total}]`: the listing's filter panels as the page
    titles them ("Precio", "Marca", "Viscosidad", "Cca (-18 Grados)"…) and up to 8 option
    labels by count, exactly as the checkboxes write them (`total` = how many options the
    panel has). "Precio" keeps all its bucket labels ("$0 - $9.999" … "Más de $500.000"),
    low to high as the page lists them: they are the filter's fixed options, not a price.
  - `pages.json` — home, /nuestras-tiendas, /sobre-nosotros, the six policy pages,
    /derco-integro, /carro (empty) and /cotizacion: `path, url, type, title, description,
    h1, sections[{heading, level, selector, text, items, volatile?}], faqs[{q, a, section,
    selector}], autoplanet_text?`. `type` is one of `PageChanged`'s kinds (home, stores,
    cart, quote, policy, page). `faqs` are the accordion panels: `q` is the panel title
    exactly as rendered (the `{faq:}` cue target), `a` the panel's text cut at ~700
    characters (a panel listing contest winners is left blank: private people).
  - `stores.json` — the 22 stores in /nuestras-tiendas order: `id` (store code SG00nn),
    `name` (as the card writes it: "Curico", "Chillan"), `address` (the card's),
    `city` (comuna), `town`, `region`, `region_code`, `phone`, `hours` ("; "-joined),
    `hours_lines`, `lat`, `lng`, `maps`.
  - `site.json` — crawl date, `nav` (the 10 level-1 nodes `{code, name, path}`),
    `shortcuts` (the red bar), `top_bar`, `footer` (`{text, href, new_tab}`), `footer_text`,
    `whatsapp`, `redirects`, `notes` for driving the site.

## Shape differences from pcfactory

- Categories are keyed by **`code`** (a string: `AG10`, `AG178`, `1001362`), not an int
  `id`; `parent_code` is added beside `parent` (still the parent's path). `page_name` is
  new: the flyout says "Lubricantes Y Fluidos", the listing page "Lubricantes y Grasas".
  `products` is the listing's `pagination.totalNumberOfResults` (the API's `countProducts`
  answers 1 whatever the listing holds).
- Facets carry `total`, keep at most 8 options (pcfactory: 25) and exist on levels 1–2
  (pcfactory: 2–3). The "Categoría" facet is dropped (a category page shows its
  sub-categories as links). The month's campaigns (`C_AG_BUSQUEDA_PLP_*`, e.g. "Agrofertas
  Octubre" on AG15 and AG12, "Accesorios Octubre" on AG02) are **kept as one facet,
  "Campaña"**, first: the page draws each as an on/off switch above "Precio" (not a panel),
  and the adapter reports and applies them under that name. They change every month.
- The home's blocks are mostly image banners with no text heading. They are sections with
  a bracketed heading (`[Carrusel principal]`, `[Marcas]`, `[Banners de categorías]`,
  `[Categorías destacadas]`, `[Productos destacados]`), which pcfactory's loader reads as
  unnamed sections; their `items` are the categories the banners link to. The two real
  headings are "Aprovecha estas oportunidades en Octubre" (`volatile: true`: the month
  changes) and "CATEGORÍAS". Selectors are `app-category-home:nth-of-type(n)`.
- Stores have no `zone`, `entry_hours`, `notice` or `stock_name` (the site has no zones
  and shows no stock per store); they add `phone` (always set), `hours_lines`, `lat`/`lng`.
- `site.json` adds `shortcuts`, `top_bar`, `footer`, `footer_text`, `whatsapp`; it has no
  `path_checks` (an SPA answers 200 for every path).

## Rebuilding

Run from `voqalize/demos`. The API part needs only Python; the page part runs
`crawl.mjs` (beside `build.py`) under node with Playwright's Chromium. Playwright is not a
demos dependency: set `PLAYWRIGHT_MODULE` to an installed copy's entry module, or let
`build.py` find one under `demos/*/extension/node_modules` (agroplanet's extension has
`@playwright/test`); its Chromium must be installed (`npx playwright install chromium`).

```sh
uv run python agroplanet/backend/knowledge/build.py api            # menu + 290 listings + stores, 1/s (~8 min)
uv run python agroplanet/backend/knowledge/build.py crawl          # 12 pages + the store cards (~2.5 min)
uv run python agroplanet/backend/knowledge/build.py maps           # site.json, L2/site-map.md, categorias.md, tiendas.md
uv run python agroplanet/backend/knowledge/build.py all --refresh  # everything, ignoring the cache
uv run python agroplanet/backend/knowledge/build.py maps --offline # from the cache only
```

The API is paced to one request a second. Every response is cached in
`~/.cache/voqalize-agroplanet` (`AGROPLANET_CACHE` overrides it). Nothing logs in or
submits a form; the browser aborts every non-GET request except one: to read the quote
form's labels the crawler adds one product to its own throwaway anonymous cart (the form
shows "Tu carro está vacío" otherwise). The site and API worked from India without a VPN.

After a rebuild, re-read `L1.md` and the hand-written L2 topics against the new crawl: the
home's heading names the month, store hours change, and the policy pages may stop sharing
Autoplanet's text.
