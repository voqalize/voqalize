# Kosha Homes — property guide and site-visit booker

A fictional Indian residential developer's website (Bengaluru, Pune, Hyderabad) with its resale and
rental desk, Kosha Exchange: 50 listings across 7 projects and 3 cities, a drawn map of each city, a
listing page, a project page, compare, shortlist and booked visits. A voice agent (today **Karthik**)
talks with the buyer and drives the screen with Stage while he talks. Everything in it, from projects
and prices to people, schools, offices, metro stations and distances, is invented.

## Landing pages and the agent's jobs

One brain, one job per landing page; it follows the visitor to another page and switches job.

| Route | Job | What the agent does |
| --- | --- | --- |
| `/demos/property/` and `/demos/property/listings` | Property guide | Narrows the listings from the buyer's description (BHK, budget, city, locality, commute to an office, schools, metro, ready to move or not): the sidebar filters tick one by one and the map follows. Rings a home as he talks about it, compares two side by side, works out an EMI from the site's lender rates, shortlists. |
| `/demos/property/listing/<id>` | Site-visit booker | Finds the slots where the buyer's day meets the sales team's diary (authored per project, IST), holds one, books it on the buyer's spoken yes, and the visit card shows address, sales contact and what to bring. |

## How it is built

- `persona.json` — the character: avatar id, display name, role, voice per language, the languages
  offered and the default. Read by the page and the brain.
- `data/homes.json` — every fact, generated by `data/build_data.py` (edit there, then
  `uv run python demos/property/data/build_data.py`).
- `CONTRACT.md` — the page ↔ brain contract: the shared search, EMI and slot rules, routes, Stage moves
  and events.
- `frontend/src/stage/scene.json` — the Stage Spec. Regenerate both halves after editing it:
  `uv run --project demos voqalize stage gen demos/property/frontend/src/stage/scene.json --py demos/property/backend/stage_gen.py --ts demos/property/frontend/src/stage/scene.gen.ts`
- `backend/` — `PropertyBrain` (`voqalize.sdk.openai.OpenAIBrain`, `reasoning="medium"`), the shared
  rules in `homes.py`, the written lines in `lines.py`, the prompt in `prompt.py`.
- `frontend/` — a standalone Vite + React app on `@voqalize/stage`, `@voqalize/avatar` and
  `@voqalize/client-transport`. `?debug=1` opens a console that fires any Stage move by hand.

## Run it

```sh
cd demos/property/frontend && pnpm install --ignore-workspace && pnpm dev --port 5409
# open http://localhost:5409/demos/property/  (add ?debug=1 for the move console)
```

For a live call set `VITE_AGENT_ID` and `VITE_PUBLISHABLE_KEY` (see `.env.example`); without them the
site works fully by click. Tests: `cd demos && uv run pytest tests/test_property_e2e.py`.

## Change the character or add a language

- **Character:** edit `persona.json` — `character` (an avatar character id), `name`, `role`, and
  `voices`. Nothing else names him: greetings, prompt, UI copy, alt text and tests read the file. Update
  the voice-contract row in `demos/tests/test_demo_voice_contract.py` if the English voice changes.
- **Language:** add it to `languages` and `voices` in `persona.json` (the voice must speak it), and add
  its written lines to every table in `backend/lines.py` (the brain refuses to import without them).
  The page's toggle picks it up from the persona file.
