# Kosha Homes — property guide and site-visit booker

A fictional Indian residential developer's website (Bengaluru, Pune, Hyderabad) with its resale and
rental desk, Kosha Exchange: 50 listings across 7 projects and 3 cities, a drawn map of each city, a
listing page, a project page, compare, shortlist and booked visits. A voice agent (today **Karthik**)
talks with the buyer and drives the screen with Stage while he talks. Everything in it, from projects
and prices to people, schools, offices, metro stations and distances, is invented.

## Landing pages and the agent's jobs

One brain, one job per landing page; it follows the visitor to another page and switches job.

| Route | Job | What the agent does |
| --- | --- | --- |
| `/demos/property/` and `/demos/property/listings` | Property guide | Sells like a good adviser: asks the few questions that narrow the homes (buy or rent, city, budget, BHK, where they work, ready or under construction, a school), never the same one twice, and searches as soon as it hears anything; the sidebar filters tick one by one and the map follows. The budget on screen is always exactly the one the buyer said; "around ₹1 crore" may offer a home up to 10% over it when nothing is at it, and when nothing fits at all it names the nearest home with how far over it is and asks before widening. Names the best home with the one number that matters (the price, said once, or the km to the office), opens and describes a home on "tell me more", compares two with a verdict, works out an EMI (two homes' EMIs side by side on request), and nudges to a site visit. Each of these steps is answered in the brain's own line straight after the model's few words of lead-in, so a turn takes one model request. |
| `/demos/property/listing/<id>` | Site-visit booker | Finds the slots where the buyer's day ("this weekend" works) meets the sales team's diary (authored per project, IST), fills the visit form as the buyer speaks (slot, name, visitors), and leaves the Mobile box to the visitor to type (never asked aloud). Once the number is in, one confirmation; the buyer's yes books it, and a personal line confirms it ("Done, Ravi! …"); the visit card shows address, sales contact and what to bring. |

## How it is built

- `persona.json` — the character: avatar id, display name, role, the dock's label per job (`roles`),
  voice per language, the languages offered and the default. Read by the page and the brain.
- `data/homes.json` — every fact, generated by `data/build_data.py` (edit there, then
  `uv run python demos/property/data/build_data.py`).
- `CONTRACT.md` — the page ↔ brain contract: the shared search, EMI and slot rules, routes, Stage moves
  and events.
- `frontend/src/stage/scene.json` — the Stage Spec. Regenerate both halves after editing it:
  `uv run --project demos voqalize stage gen demos/property/frontend/src/stage/scene.json --py demos/property/backend/stage_gen.py --ts demos/property/frontend/src/stage/scene.gen.ts`
- `backend/` — `PropertyBrain` (`voqalize.sdk.openai.OpenAIBrain`, `reasoning="medium"`), the shared
  rules in `homes.py`, the written lines in `lines.py`, the prompt in `prompt.py`.
- `backend/spoken.py` — amounts in speech, both ways. Everything the agent says (the model's words and
  its own lines) is rewritten where the TTS still needs it: a range with the scale said once is spelled
  out ("₹1 to 1.5 crore" would be read "one rupee to 1.5 crore"), and in Hindi a price is whole rupees, or
  सवा / डेढ़ / साढ़े with लाख and करोड़. A single English price ("₹1.14 crore") goes as written: the TTS
  reads it right since speech 174bd6ef. What the buyer says ("1 to 1.5 crore", "dedh crore", "45k a month",
  "सवा करोड़") reaches the model as rupees, and a budget no buyer would mean (₹15) is confirmed back
  before the search uses it.
- `frontend/` — a standalone Vite + React app on `@voqalize/stage`, `@voqalize/avatar` and
  `@voqalize/client-transport`. `?debug=1` opens a console that fires any Stage move by hand and can
  fake a call to show the call tile.
- The agent widget (`frontend/src/voice/`, Paynora's): idle, a bar at the bottom with the character's
  still photo, the job on this page, EN / हिंदी and "Talk to {name}"; in a call the bar goes away and a
  draggable face tile (`CallTile.tsx`) holds the live avatar, the language toggle, mute, minimise and
  end. No transcript. The language is remembered across reloads; the phone's filter sheet moves the
  agent to a top corner (`useDockMode.ts`). Every highlight first scrolls the target's whole group into
  view, inner scroll areas included (`frontend/src/stage/view.ts`).

## Run it

```sh
cd demos/property/frontend && pnpm install --ignore-workspace && pnpm dev --port 5409
# open http://localhost:5409/demos/property/  (add ?debug=1 for the move console)
```

For a live call set `VITE_AGENT_ID` and `VITE_PUBLISHABLE_KEY` (see `.env.example`); without them the
site works fully by click. Tests: `cd demos && uv run pytest tests/test_property_e2e.py`.

## Change the character or add a language

- **Character:** edit `persona.json` — `character` (an avatar character id), `name`, `role`, `roles`
  and `voices`, and add the idle dock's still photo at `frontend/src/characters/<character>.webp`. Nothing else names him: greetings, prompt, UI copy, alt text and tests read the file. Update
  the voice-contract row in `demos/tests/test_demo_voice_contract.py` if the English voice changes.
- **Language:** add it to `languages` and `voices` in `persona.json` (the voice must speak it), and add
  its written lines to every table in `backend/lines.py` (the brain refuses to import without them).
  The page's toggle picks it up from the persona file.

## Redial

A call survives a dropped brain socket (SDK 0.15.0 `Config.redial`): where Voqalize offers it, the
brain turns redial on, keeps each call in memory by session id for two minutes after its socket
drops (`backend/rejoin.py`), and the brain a redial starts picks the call up where it was (page,
language, search, shortlist, a visit held for a yes, the model's history) without greeting again.
Details in CONTRACT.md, "Redial". Tests: the `redial` cases in `demos/tests/test_property_e2e.py`.
