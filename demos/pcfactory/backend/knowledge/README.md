# PC Factory knowledge

What the PC Factory agent (Javier, in a Chrome extension on www.pcfactory.cl) knows, in
three layers. Every fact is the site's own, read on 2026-10-29 from www.pcfactory.cl and
api.pcfactory.cl; nothing is filled in from general knowledge. Where the site disagrees
with itself the disagreement is written down, not resolved. **No file holds a product
price or a stock level**: prices (Transferencia / Débito, Otros medios de pago, referencia)
and stock are read live in the visitor's browser and reach the brain as app and stage
events.

- **`L1.md`**: always in the prompt, ~2.5k tokens, hand-written and dated: who pcFactory
  is, the 16 top categories and the most-asked ones with their paths, the three prices and
  how to say them, despacho, retiro, garantía, medios de pago, Empresas, the phone, tú.
- **`L2/<topic>.md`**: read on demand; the file stem is the topic id; each opens with
  `# Title` and a `Sources:` line. Hand-written: `despacho`, `retiro-en-tienda`,
  `medios-de-pago`, `garantia-y-devoluciones`, `stock`, `como-comprar`, `tiendas`,
  `empresas`, `arma-tu-pc`, `eventos-y-cupones`, `centro-de-ayuda` (every question and
  answer of every Centro de ayuda topic). Generated by `build.py maps`: `site-map` (pages,
  headings, FAQ questions) and `categorias` (the tree with ids, paths and filters).
- **`L3/`**, built by `build.py` and committed, one object a line inside `[ ]`:
  - `categories.json` — every node of the site's menu tree (`/menu` API): `id, path`
    (`/categoria/...`), `name, parent, level, aliases` (the other paths of the same id),
    `products` (listed that day, from the brand counts) and, for levels 2 and 3, `facets`
    `[{name, param, options}]` as the listing's checkboxes write them ("Sucursales" is
    "Tiendas" on the page, a blank option is "Otros"; "Rango de precios" and "Tiendas" are
    left out).
  - `pages.json` — home, /tiendas, /categorias, the Centro de ayuda hub and topics,
    /empresas, /arma-tu-pc, the live campaign pages, /estado-despacho, Asesórate Online
    and the 16 top category pages: `path, url, type, title, description, h1,
    sections[{heading, level, selector, text, items}], faqs[{q, a, section, selector}]`.
    Headings are what the page renders after JS and scrolling; `{show:}` cues name them
    and `{faq:}` cues name the questions. `selector` is "" when nothing stable is unique.
  - `stores.json` — the 28 stores: `id` (the stock API's store id), `name` (as /tiendas
    writes it), `zone` (/tiendas tab), `address`, `local`, `city`, `region`, `hours` (the
    "Ver tienda" map card's text), `entry_hours` (the store entry's own text, which can
    differ), `notice`, `stock_name` and `stock_zone` (how the stock API and the listing's
    Tiendas filter name it).
  - `site.json` — crawl date, the top-level nav, category path checks and notes for
    driving the site.

## Rebuilding

Run from `voqalize/demos`. The API part needs only Python; the page part runs
`crawl.mjs` (beside `build.py`) under node with Playwright's Chromium. Playwright is not a
demos dependency: set `PLAYWRIGHT_MODULE` to an installed copy's entry module, or let
`build.py` find one under `demos/*/extension/node_modules` (`@playwright/test` or
`playwright`); its Chromium must be installed (`npx playwright install chromium`).

```sh
uv run python pcfactory/backend/knowledge/build.py api            # /menu + 227 facet calls, 1/s (~4 min)
uv run python pcfactory/backend/knowledge/build.py crawl          # ~40 page loads + /tiendas map cards
uv run python pcfactory/backend/knowledge/build.py maps           # site.json, L2/site-map.md, L2/categorias.md
uv run python pcfactory/backend/knowledge/build.py all --refresh  # everything, ignoring the cache
uv run python pcfactory/backend/knowledge/build.py maps --offline # from the cache only
```

The API is paced to one request a second. Every response is cached in
`~/.cache/voqalize-pcfactory` (`PCFACTORY_CACHE` overrides it). A campaign page that has
ended redirects and is skipped. Nothing here logs in, submits a form or touches the cart;
the browser aborts every non-GET request. The site worked from India without a VPN.

After a rebuild, re-read `L1.md` and the hand-written L2 topics against the new crawl:
campaigns and coupons (`eventos-y-cupones`) change weekly, and store hours carry holiday
notes.
