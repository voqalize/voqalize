# Saint George's College knowledge

What the Saint George's College agent (Javier, a Chrome extension on saintgeorge.cl) knows, in
three layers. Every fact is the site's own; nothing is filled in from general knowledge. Where the
site's pages disagree (seven vs three founding priests, the 1943/1944 handover, "casi 90 años" vs
90 years in 2026), the files record which page says what. They do not resolve it.

The hand-written layers are in **Spanish**, the site's only language, keeping the site's own names
(including the English unit names Infant, Elementary, Junior, Senior).

**Changing data is marked `[en vivo]`.** Admission status and vacancies, the "Valores referenciales"
in UF, the Google Calendar, ticket sales for the musical, the monthly casino menus and the newsletter
list change during the year. The files say *where* each lives (path, heading, selector) and tell the
agent to read it from the live page. The UF values and the admission status ("Admisión 2027: …")
are not written in L1/L2 at all (the brain's loader also masks both in L3, so a rebuild cannot
bring them back); the few other changing values kept are labelled "foto 2026-10-22",
as santanderarena and clini keep their dated snapshots.

- **`L1.md`**: always in the prompt. Who the school is, history in short, mission and values, the
  four units with their course numbers, admissions in short (where the live data is), English and
  Cambridge, pastoral, sports, families' pages, the portals on other hosts, contact, what the site
  does not have, the menu, and the list of L2 topics. About 3k tokens.
- **`L2/<topic>.md`**: a topic the agent reads on demand. The file stem is the topic id. Each file
  opens with `# Title`, then a `Sources:` line. Hand-written from L3, except `site-map.md`, which
  `build.py` generates (every non-empty page with its exact headings, accordion buttons, anchors,
  PDFs, external links and iframes, plus the menu and the list of empty pages). Topics:
  `admisiones-y-aranceles`, `niveles`, `programa-academico`, `pastoral-y-formacion`,
  `area-deportiva` (includes a summary of the two 2026 sports PDFs), `calendario-y-eventos`,
  `musical-90-anos`, `the-dragon`, `vida-escolar-familias`, `documentos-institucionales`,
  `historia-y-congregacion`, `accesos-y-portales`, `contacto`, `faq`, `site-map`.
- **`L3/`**: generated by `build.py`, the searchable and highlightable raw material.
  - `pages.json`: every page that answered 200, one compact record per line. It keeps the keys the
    shared loader reads (`path`, `title`, `description`, `sections: [{heading, text, items}]`,
    `headings`, `faqs: [{q, a}]`, `text`), so `knowledge.py` reads it like santanderarena's. It adds
    `url`, `kind`, `modified` (from wp-json), `empty`, section `level`/`selector`/`pseudo`/`dom_text`,
    accordion detail on each FAQ (`target`, `nth`, `nth_label`, `group_id`, `rows`…), `cards`,
    `documents` (PDF links), `links` (links that leave the site), `forms`, `iframes`, `anchors`.
    The `build.py` docstring defines each. Accordions are the FAQs: their button text is `q`.
  - `sections.json`: per path, every target a page move can use: headings with selectors, in-page
    anchors (`#comunidad`, `#mision`, `#valores` on the home page), accordions with a `find` rule
    (folded button label, plus `nth_label` when a label repeats), PDFs, external links, iframes.
  - `levels.json`: the four units with their grade accordions, the page's own cycle sentence and
    its sentences about courses and staff, verbatim.
  - `site.json`: the menu (`#menu-menu-1`, nested, with which items only open a dropdown), the
    footer (address, phones, e-mail, links), response headers, redirects, broken links, empty
    pages, the sitemaps and wp-json type counts, every outbound link and the calendar embed.
  - `documents.json`: every linked PDF and the pages that link it. Only written with `--pdfs`. The
    text pypdf extracts (files up to 12 MB, capped at 8,000 characters) stays in the local cache,
    because some PDFs carry third parties' bank details; the L2 topics summarise the useful ones.

## Rebuilding

Run from `voqalize/demos`. Playwright and pypdf are not demos dependencies, so pull them in for the
run (install Chromium once with `playwright install chromium`):

```sh
uv run --no-project --with playwright --with pypdf python saintgeorge/backend/knowledge/build.py crawl --pdfs
uv run --no-project --with playwright python saintgeorge/backend/knowledge/build.py crawl --refresh
uv run --no-project --with pypdf python saintgeorge/backend/knowledge/build.py crawl --offline --pdfs
```

`crawl` reads the Yoast sitemap index (16 sub-sitemaps) and the public wp-json listings, then
renders `/`, every sitemap URL and every same-host link they reach (about 70 pages, two at a time
with a pause between pages; the PDFs one at a time). Each extraction is cached in
`~/.cache/voqalize-saintgeorge`. `--refresh` re-renders everything; `--offline` rebuilds L3 and
`site-map.md` from the cache. No form is ever submitted. If the site answers 403/405 or "Not
allowed" three times running, the build stops and writes nothing: the site refuses some countries,
so run it from a connection it accepts. After a crawl, update the hand-written L2 files and L1 if a
page changed.

## Things to know about the site

- **WordPress, custom theme, server-rendered.** Theme `colegio-saint-george`, Bootstrap 5, jQuery.
  Every navigation is a full page load. No page builder, no SPA routing.
- **REST has no text.** The custom post types (`admision`, `unidad`, `colegio`, `familia`,
  `formacion-integral`, `the-dragon`, `equipo-directivo`, `congregacion`) render from fields the
  REST API does not expose: `content.rendered` is empty. wp-json is used only for the list of
  entries and their `modified` dates; every word comes from the rendered page.
- **Accordion ids repeat on every page.** Bootstrap 5 collapses: `button.accordion-button
  [data-bs-target="#collapse_X_Y"]` → `.accordion-collapse`. `#collapse_1_1` is "Dirección y equipo
  Infant" on one page and "CONOCE AL EQUIPO" on another. Find a button by its text on the current
  page. Buttons render in capitals (CSS `text-transform`); `q` keeps the DOM text. Each accordion
  is its own group, so several can be open at once. Panels hold staff tables (names).
- **Top-level menu items do not navigate.** Colegio, Familia, Formación integral, Admisión and
  Comunidad are dropdown toggles. Their own URLs (`/admision/`, `/formacion-integral/`,
  `/comunidad/`, `/documentos-institucionales/`, `/aprender-a-*`) render WordPress's default
  template (a search box and "Recent Posts"); so do `/equipo-directivo/<name>/`, `/the-dragon/*`,
  the taxonomy pages and the photo attachment pages under `/familia/ropero/`. They are in
  `pages.json` with `empty: true` and are left out of `sections.json` and the site map.
- **No forms.** Admissions and contact are e-mail and phone only. The only `<form>`s are WordPress
  search boxes on the empty pages. Payments, elective applications, Schoolnet and LIRMI are logins
  on other hosts (`sistemas.saintgeorge.cl`, `schoolnet.colegium.com`, `login.lirmi.com`); jobs are
  on `saintgeorge.profejobs.cl`.
- **Admission details are plain paragraphs.** `/admision/admision/` is a few `<p>` with bold
  lead-ins ("Admisión 2027:", "Admisión Pre Kínder 2028:", "Valores referenciales año 2026:"); the
  admissions e-mail is text, not a link.
- **The calendar is a cross-origin iframe.** `/familia/calendario/` embeds Google Calendar twice
  (`iframe.calendar-desktop`, month view; `iframe.calendar-mobile`, agenda view, under 992 px). The
  page cannot read it and the crawl holds no events.
- **Much is only in PDFs.** The newsletter (The Dragon), supply lists, menus, reglamentos, plans and
  the sports schedule are PDF buttons (`a.btn.btn-blue`). Some are large (Informativo 2026 ~24 MB,
  Plan Curricular ~21 MB) and are listed without text.
- **Stale staging links.** `/colegio/` repeats the Proyecto Educativo text, but its buttons point to
  `bbyte.cl/clientes/wp-sg/...`, a broken staging copy. Some images on other pages load from there
  too.
- **Headers.** nginx; `x-frame-options: SAMEORIGIN`; no `permissions-policy` and no CSP (checked on
  every page), so the microphone is not blocked by the site.
- **Fixed header.** `nav#navbar` is fixed and about 130 px tall: scroll targets need an offset.
  Content blocks fade in (`animate__animated`) when scrolled into view.
- **Spanish only.** `<html lang="es">`, no English version. A visitor's Chrome may auto-translate
  the page, which breaks text matching; prefer href- and class-based selectors.
