# Saatvik knowledge

What the Saatvik agent knows, in three layers. Every fact is Saatvik Green
Energy's own, taken from www.saatvikgroup.com and the PDFs it links. Nothing is
filled in from general knowledge. Where Saatvik's own pages disagree, the files
record the disagreement and say which page to quote; they do not resolve it.

- **`L1.md`**: always in the prompt. The company, every product line in brief,
  PM Surya Ghar in brief, the calculator, warranties, contacts, and the list of
  L2 topics. Keep it small enough to sit in every request (about 3k tokens today).
- **`L2/<topic>.md`**: a topic the agent reads on demand. The file stem is the
  topic id. Each file opens with `# Title`, then a `Sources:` line naming the
  pages and PDF pages it was written from. L2 is hand-written from L3 and cites
  the page for anything a visitor might quote back.
- **`L3/`**: generated by `build.py`, the searchable and highlightable raw
  material.
  - `pages.json` holds every site page: headings, FAQs, stats, tables and text.
  - `documents.json` holds every product PDF, page by page.
  - `investor_documents.json` lists the investor filings without their text.
  The schemas are in `build.py`'s docstring.

## Rebuilding L3

From `voqalize/demos`:

    uv run python saatvik/backend/knowledge/build.py crawl            # fetch what is not cached
    uv run python saatvik/backend/knowledge/build.py crawl --offline  # cache only
    uv run python saatvik/backend/knowledge/build.py crawl --refresh  # re-download and re-OCR
    uv run python saatvik/backend/knowledge/build.py search "temperature coefficient"

Downloads and OCR results are cached in `~/.cache/voqalize-saatvik`.

OCR needs poppler's `pdftoppm` and `tesseract` (`brew install poppler
tesseract`). A rebuild changes L3 only. When it surfaces new facts, update L2
and L1 by hand.

## Things to know

- **PDF page numbers are page indexes** (1-based), not the folio printed on the
  page. That is what the browser's PDF viewer opens with `#page=N`.
- **OCR'd pages.** Some PDFs draw their text as outlines, so the text layer is
  empty or carries numbers without labels. This covers the module datasheets,
  the scanned installation manual and parts of the inverter guides. Those pages
  carry `ocr: true` and a `words` list of `[word, x0, y0, x1, y1]` boxes, as
  fractions of the page with a top-left origin. The viewer can use the boxes to
  highlight a quote that has no text layer. OCR can misread characters, so
  check a figure against the product page before relying on it.
- **Left out on purpose:**
  - Investor PDFs are listed, not read.
  - Dealers' names and personal phone numbers stay out of L1 and L2; the agent
    sends people to `/dealer-locator`.
  - State-level subsidy figures, because Saatvik's blogs disagree with each
    other and they change.
  - Outdated blog text on the old MNRE 40%/20% CFA scheme.
  - Product prices, which Saatvik does not publish.
- The site serves its FAQ answers collapsed in the server HTML. Its animated
  counters render as 0 there, and the build recovers them from the Next.js
  flight data (`stats`).
