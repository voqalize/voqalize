# Figurella Chile knowledge

What the Figurella agent (Javier, a Chrome extension on figurella.cl) knows, in three layers.
Every fact is the site's own; nothing is filled in from general knowledge. The hand-written layers
are in **Spanish**, the site's only language, keeping the site's own names (Curvas perfectas,
Mamá reciente, Huérfanos, presoterapia).

**What the site does not say is written down first.** figurella.cl publishes no price, no plan
length, no session count and not the terms of the written guarantee it promises; "Plan Ideal" is
named only in two agreements; there is no booking calendar (the form is a lead, and the branch
calls back). `L1.md` opens with that list so the agent says "se define en la evaluación gratis"
rather than guessing, and the e2e test checks the prompt has no money in it.

- **`L1.md`**: always in the prompt. What the site does not say, who Figurella is, the method's
  steps, the five plans (with which goal each fits), the six FAQ questions, the three success
  stories, the fourteen agreements, the seven branches with addresses, phones and hours, the booking
  form, franchises, the blog and the menu. About 3k tokens.
- **`L2/<topic>.md`**: a topic the agent reads on demand with `read_topic`. The file stem is the
  topic id. Each file opens with `# Title`, then a `Sources:` line. Hand-written from the site,
  except `site-map.md`, which `build.py` generates from the catalogue. Topics: `consejos` (the 14
  blog posts with their paths and what each says), `testimonios` (the three stories in full),
  `garantia-y-precios` (everything the site says about the guarantee and prices, and what it does
  not), `privacidad`, `site-map`.
- **`L3/`**: generated by `build.py` from the live site (headless Chromium, plus the open WordPress
  REST API for the posts).
  - `anchors.json`: **the catalogue of places**, shared by the brain and the extension. For every
    page path, `{kind, footer, anchors: [{key, selector, label, hidden?}]}`; the footer's anchors
    (the booking form `#contacto` and its fields), on every page whose `footer` is true; the blog
    post template's; and the FAQ's questions by key (`faq_precio` → `#cunto-cuesta-figurella`).
    Every selector matched exactly one laid-out element on the live page when it was built; the
    selectors are Elementor's stable `.elementor-element-<id>` classes and the site's own ids.
    `hidden` places are the adapter's own (a field it fills, a button it listens to) and are never
    offered to the model. The extension bundles this file; the brain checks every cue against it.
  - `pages.json`: one record per page and per blog post: `{path, url, title, kind, sections: [{key,
    heading, text}], faqs: [{q, key, a}], text, date}`. A section is a place of the catalogue with
    the words the element showed (`innerText`, capped); `search_site` searches them and the brain
    matches what he says against them to ring the place he describes.
  - `branches.json`: the seven branches as their cards give them (name, address, phone, hours, the
    "¿Cómo llegar?" map link), the booking form's option value for each, the WhatsApp widget's
    number, and Montemar (Concón), which is only in the WhatsApp widget.
  - `convenios.json`: the fourteen agreements: partner (from the logo's file name where the card
    has only a logo), discount, the card's text.

Which branch is nearest a comuna is not on the site; it is the brain's own table
(`../comunas.py`), judged from the branches' addresses, and the agent offers it as a suggestion.

## Rebuilding

Run from `voqalize/demos` on a machine the site answers (it is geo-blocked from some countries,
India among them; the brain, which runs there, never fetches it). Playwright is not a demos
dependency, so pull it in for the run (install Chromium once with `playwright install chromium`):

```sh
uv run --no-project --with playwright python figurella/backend/knowledge/build.py crawl
uv run --no-project python figurella/backend/knowledge/build.py crawl --offline
```

`crawl` renders every page of the catalogue and every blog post, closes the bottom bar, scrolls
through, checks each selector and reads each place's words, caching the result in
`$XDG_CACHE_HOME/voqalize-figurella` (`~/.cache` by default); `--offline` rebuilds from that cache.
An anchor whose selector no longer matches exactly one laid-out element is dropped and printed, so a
re-edit of the site shows up as a short catalogue rather than as a move that rings nothing. After a
rebuild, run `pnpm build` in `../../extension` (it bundles `anchors.json`) and the demo tests.

The page fixtures the page test runs against are saved separately, by `../../fixtures/fetch.py`.
